The plan for every counting problem

Weeks 4 and 5 use one plan. Start by pretending everything is distinct, because the rule of product “creates order and treats objects as being distinct”. Then fix what that count got wrong.

  1. Draw one answer. What's in it? Which things are different, which look alike? Is one answer a set (a group) or a sequence (a line, a word)?
  2. Distinct build: first, and then. Multiply, but only if each step has the same number of choices whatever came before. Start with the most restricted spot.
  3. Fix the count. Same number of copies? Divide. A choice behaves differently, or the copies are uneven? Disjoint cases, add (if two cases overlap, subtract the overlap). “At least one”, or too many cases? Total − complement.
  4. Check a tiny case. List it, or count the same thing a second way.

The key test in step 3: was every answer built the same number of times? If yes, divide by that number. If some answers were built more often than others, no single division works: split into cases, or count the complement.

Permutation or combination?

Combination: order does not matter. AB = BA.

Picking A then B gives the same group as picking B then A, so a combination counts them as one.

Permutation: order matters. AB ≠ BA.

If A is first and B is second (say, captain and helper), swapping them gives a different outcome, so a permutation counts AB and BA as two.

AB and BApairs from A, B, C, D, E
permutation (order matters)2 outcomes5 × 4 = 20

This is where the two ideas split, and the teacher draws the line himself in his opening note: “Rule of product creates order and treats objects as being distinct.” His definition: “Combination: a group without order.”

  • Permutation. The rule of product creates order and treats the objects as distinct. Choosing 3 of 5 friends one at a time gives 5 × 4 × 3 = 60 ordered lists.
  • Combination. A group without order. The same 3 people in a different order are the same group, so each group was counted once for each of its 3! = 6 orders, and we divide: 60 ÷ 6 = 10.

His recall example, A, A, A, B, C, is the same correction in a different setting: the identical A’s were counted as if they were different (5! = 120), then the overcount was fixed by dividing by 3! (120 ÷ 6 = 20).

The tag word shows the difference in one picture. The only change is whether the chosen objects get different tags or the same tag:

Order matters: president, vice-president, secretary

Different tags P, V, S. Swapping two of the chosen friends changes the outcome: a permutation.

Order doesn’t matter: a sleepover group

The same tag T for all three. Swapping two of them changes nothing: a combination, a group without order.

The choose function (Proposition 1.1)

nCk = nk = n!k! × (n − k)!

The number of ways to choose k objects from n available. It has three names on paper, and all of them are read “n choose k”: nCk, the tall bracket (n over k), and the formula. The teacher also calls it the binomial coefficient.

In the tag word it is a word with k T’s and n − k L’s. It is also the permutation count with the order removed: n! ÷ (n − k)! counts with order, and dividing by k! removes it. For the sleepover, 5C3 = 5! ÷ (3! × 2!) = 10.

On the workbench pages you can type it any of these ways: 5C3, C(5, 3) or “5 choose 3”.

The one question to ask

If I swap two of the chosen things, is it a new outcome?

  • Yes: each chosen thing gets its own tag (like P, V, S). It’s a permutation, and only the unused L’s are divided out.
  • No: they all get the same tag, T. It’s a combination, and the T’s are divided out as well. That extra ÷ 3! is the “overcount was dealt with” from the slide.

The problem set uses both. Problem 15 has a small permutation inside it: the column tags 1, 2, 3 are all different, because each column belongs to a specific row. Problem 1 is a pure combination, with the identical tags T, T, T.

Week 5: cases add, steps multiply

Every Week 5 problem has the same shape, so we always do it the same way:

  1. Make the cases first. “Either ___ or ___.” The cases must be disjoint (no answer in two cases). Make a case wherever a decision behaves differently, like a first digit that can’t be 0.
  2. Inside each case, multiply the steps. “First ___, and then ___.”
  3. Add the cases.

That’s the easy way to tell multiplication from addition: × happens inside a case, + happens between cases.

When the cases get messy (“at least one” could mean 1, 2, 3 or 4…), count the opposite instead. Listen for the words: “contains” → “at least one” → complementary counting. Then count you want = Total − the rest (complementary counting). It’s still two cases, the ones you want and the rest, that add up to the total.

How grading works

Each problem is split into steps, one number per step. He writes his method in the lined box and types the number (or an expression like 12 choose 4 or 2^6 × 11), then presses Check step (Enter in the answer box, Ctrl+Enter in the working box).

A wrong answer gets a nudge, and the nudges get more specific each time. After three misses he gets one final attempt; if that misses too, the step's answer is handed over and he does the next step himself. Hint for this step opens a hint without using a try (it's noted in My steps). Submit question reports how each step went and opens the verified answer and a step-by-step picture story once every step is closed. Show worked answer asks twice if some steps haven't been tried.

Nothing is saved when the tab closes: progress and ink start fresh each visit.
